 LATAR BELAKANG
Dalam era transformasi digital yang berkembang pesat, pengelolaan proyek perangkat lunak secara efisien menjadi tantangan utama bagi tim pengembang modern. Komunikasi yang tidak terstruktur, ketidakjelasan pembagian tugas, dan sulitnya memantau progres pekerjaan antaranggota tim seringkali menjadi akar permasalahan dalam kegagalan proyek perangkat lunak (
software project failure
).
 
Berdasarkan laporan 
Standish Group Chaos Report
, lebih dari 60% proyek perangkat lunak mengalami keterlambatan, pembengkakan biaya, atau kegagalan total. Sebagian besar disebabkan oleh lemahnya koordinasi tim dan tidak adanya sistem manajemen yang terpusat. Kondisi ini semakin krusial ketika tim bekerja secara 
remote
 atau tersebar (
distributed team
) di berbagai lokasi.
 
Solusi manajemen proyek yang ada saat ini—seperti Jira, Trello, atau Asana—menawarkan fitur yang kaya, namun sering kali terlalu kompleks, berbayar mahal, dan tidak dirancang spesifik untuk kebutuhan tim pengembang kecil hingga menengah yang membutuhkan 
standarisasi kode
, 
onboarding developer baru
, dan 
monitoring progres berbasis checklist teknis
 secara bersamaan.
Atas dasar permasalahan tersebut, Kelompok
 8
 merancang dan mengimplementasikan 
DevFlow
 — sebuah sistem manajemen proyek 
enterprise
 berbasis web yang dibangun di atas teknologi 
full-stack
 modern: 
Next.js 14
 sebagai 
framework
 front-end dan 
Firebase
 sebagai 
backend-as-a-service
 dengan kemampuan 
real-time database
. DevFlow dirancang untuk memenuhi tiga kebutuhan spesifik tim pengembang:
 
1. 
Pemusatan progres internal tim
 melalui dashboard intelijen bisnis berbasis data 
real-time
.
2. 
Standarisasi kode
 (
Code Standards
) yang dapat diperbarui secara terpusat dan langsung terpantulkan ke seluruh anggota tim.
3. 
Orientasi kerja developer baru
 (
onboarding
) melalui checklist tugas terstruktur tanpa miskomunikasi.
 
 
1.2 RUMUSAN MASALAH
Berdasarkan latar belakang yang telah diuraikan, maka rumusan masalah dalam makalah ini adalah:
 
1. Bagaimana merancang sistem manajemen proyek berbasis web yang mampu menampilkan progres tim secara 
real-time
 tanpa perlu 
refresh
 halaman browser?
2. Bagaimana mengimplementasikan sistem 
Role-Based Access Control (RBAC)
 yang efektif untuk membedakan hak akses antara 
Project Manager
 (Admin) dan 
Developer
 dalam satu platform terintegrasi?
3. Bagaimana membangun mekanisme 
CMS Checklist
 yang bersifat dinamis sehingga Admin dapat mengelola daftar tugas secara langsung tanpa perubahan kode (
no-code update
)?
4. Bagaimana merancang arsitektur database 
NoSQL
 menggunakan Firebase Firestore yang mampu mendukung sinkronisasi data lintas pengguna secara efisien?
5. Bagaimana mengintegrasikan fitur 
pelaporan otomatis
 berbasis konversi tampilan browser ke format laporan yang siap cetak/presentasi
1.3 TUJUAN PENELITIAN
1.3.1 Tujuan Umum
Merancang dan mengimplementasikan aplikasi web 
DevFlow
 sebagai solusi manajemen proyek 
enterprise
 yang efisien, real-time, dan mudah digunakan oleh tim pengembang perangkat lunak.
 
1.3.2 Tujuan Khusus
1. Membangun 
sistem dashboard intelijen
 yang menampilkan metrik performa tim secara 
real-time
, termasuk 
Pending Checklists
, 
Team Alignment
, dan 
Standards Drift
.
2. Mengimplementasikan 
RBAC dua-tingkat
 (Admin/PM dan Developer) menggunakan Firebase Authentication dengan Google OAuth2.
3. Merancang 
CMS Checklist dinamis
 yang memungkinkan Admin menambah, mengubah, dan menghapus tugas (
global_tasks
) yang langsung tersinkronisasi ke seluruh Developer melalui WebSocket Firebase.
4. Membangun modul 
Team Progress (X-Ray Mode)
 yang memberikan visibilitas penuh kepada PM mengenai tugas spesifik yang belum diselesaikan oleh masing-masing anggota tim.
5. Mengimplementasikan 
Code Standards Wiki
 terpusat yang dapat diperbarui Admin dan langsung terefleksikan ke seluruh penggu
 
na sistem secara sinkron.
6. Mengintegrasikan fitur 
Report Generation
 berbasis Native Browser Print API untuk menghasilkan laporan progres tim dalam format PDF/cetak.
1.4 MANFAAT PENELITIAN
1.4.1 Manfaat Teoritis
Memberikan kontribusi akademis dalam pengembangan aplikasi 
full-stack
 berbasis arsitektur 
JAMstack
 (JavaScript, API, Markup) menggunakan Next.js dan Firebase.
Menjadi referensi implementasi pola desain 
RBAC
 pada sistem manajemen proyek berbasis web modern.
Mendemonstrasikan penerapan 
WebSocket real-time
 melalui Firebase Firestore 
onSnapshot()
 listener dalam konteks aplikasi kolaboratif.
 
1.4.2 Manfaat Praktis
Bagi Tim Pengembang:
 Menyediakan platform terpusat untuk memantau progres, menstandardisasi kode, dan mempercepat proses 
onboarding
 developer baru.
Bagi Project Manager:
 Memberikan visibilitas penuh (
full transparency
) atas kinerja dan progres setiap anggota tim melalui dashboard yang akurat dan real-time.
Bagi Institusi/Perusahaan:
 Mengurangi biaya komunikasi dan risiko miskomunikasi antar anggota tim yang bekerja secara terdistribusi (
remote work
).
Bagi Akademisi:
 Menyediakan studi kasus implementasi teknologi web modern dalam konteks sistem informasi manajemen.
1.5 BATASAN MASALAH
Agar penelitian ini tetap terfokus dan dapat diselesaikan dalam batas waktu yang ditentukan, maka batasan masalah yang ditetapkan adalah:
 
1. Sistem DevFlow dikembangkan sebagai aplikasi 
web-based
 dan tidak mencakup pengembangan aplikasi mobile (
native iOS/Android
).
2. Autentikasi pengguna menggunakan 
Google OAuth
 melalui Firebase Authentication; metode autentikasi lain tidak termasuk dalam ruang lingkup.
3. Sistem hanya mendukung 
dua tingkatan peran
 (
role
): Admin/Project Manager dan Developer.
4. Fitur notifikasi 
push
 (
email/SMS
) tidak termasuk dalam implementasi; notifikasi dilakukan secara visual melalui antarmuka aplikasi.
5. Penyimpanan data sepenuhnya menggunakan 
Firebase Firestore
 (NoSQL); migrasi ke database relasional tidak termasuk dalam lingkup.
6. Sistem dikembangkan dan diuji pada lingkungan 
development
 (
localhost:3000
).
 
BAB II
2.1 TINJAUAN PUSTAKA
2.1
.1
 Manajemen Proyek Perangkat Lunak
Manajemen proyek perangkat lunak adalah disiplin ilmu yang mencakup perencanaan, 
.
pelaksanaan, pemantauan, dan pengendalian proyek pengembangan perangkat lunak (Pressman, 2010). Efektivitas manajemen proyek bergantung pada ketersediaan alat (
tools
) yang mendukung koordinasi tim, transparansi progres, dan standarisasi proses.
 
2.1.2 Real-Time Web Application
Aplikasi web 
real-time
 memungkinkan pertukaran data antara klien dan server terjadi secara instan tanpa memerlukan 
polling
 atau 
refresh
 halaman. Teknologi WebSocket dan solusi 
Backend-as-a-Service
 seperti Firebase Firestore memungkinkan pembangunan aplikasi kolaboratif dengan latensi sangat rendah, yakni rata-rata di bawah 50ms (Grigorik, 2013).
 
2.1.3 Next.js sebagai Framework Full-Stack
Next.js adalah 
framework
 React yang dikembangkan oleh Vercel, mendukung 
Server-Side Rendering
 (SSR), 
Static Site Generation
 (SSG), dan 
App Router
 berbasis React Server Components. Kemampuan pemisahan antara komponen server dan komponen klien (
use client
) memungkinkan optimasi performa superior (Vercel, 2024).
 
2.1.4 Firebase Firestore sebagai Real-Time Database
Firebase Firestore adalah 
cloud-hosted NoSQL database
 yang menyediakan sinkronisasi data 
real-time
 melalui listener 
onSnapshot()
. Setiap perubahan data pada server langsung dikirimkan ke semua klien yang terhubung dalam latensi rata-rata < 50ms, menjadikannya ideal untuk aplikasi kolaboratif (Google Firebase, 2024).
 
2.1.5 Role-Based Access Control (RBAC)
RBAC adalah model kontrol akses di mana hak akses diberikan berdasarkan peran (
role
) pengguna dalam sistem. Model ini menyederhanakan administrasi keamanan dan memastikan prinsip 
least privilege
 diterapkan secara konsisten (Sandhu et al., 1996).
 
2.1.6 Glassmorphism dalam UI/UX Design
Glassmorphism adalah tren desain antarmuka yang mengedepankan efek kaca semi-transparan (
frosted glass
), banyak digunakan dalam aplikasi 
dark mode
 modern. Dikombinasikan dengan skema warna 
cyberpunk/dark indigo
, desain ini menciptakan pengalaman visual yang premium dan profesional.

3.1.5 Mekanisme Real-Time dengan onSnapshot()
         
    // Implementasi real-time listener Firebase Firestore    
    const unsubscribe = onSnapshot(    
      collection(db, "global_tasks"),    
      (snapshot) => {    
        const tasks = snapshot.docs.map(doc => ({    
          id: doc.id,    
          ...doc.data()    
        }));    
        setTasks(tasks); // Update state React secara otomatis    
      }    
    );    
         
    // Cleanup listener saat komponen unmount    
    return () => unsubscribe();

.6 Implementasi RBAC dengan Firestore Security Rules
         
    rules_version = '2';    
    service cloud.firestore {    
      match /databases/{database}/documents {    
            
        function isAdmin() {    
          return request.auth != null &&     
                 get(/databases/$(database)/documents/users/$(request.auth.uid))    
                 .data.role == "admin";    
        }    
            
        // global_tasks: semua bisa baca, hanya admin bisa CRUD    
        match /global_tasks/{taskId} {    
          allow read: if request.auth != null;    
          allow create, update, delete: if isAdmin();    
        }    
            
        // settings: semua bisa baca, hanya admin bisa ubah    
        match /settings/{settingId} {    
          allow read: if request.auth != null;    
          allow write: if isAdmin();    
        }    
      }    
    }
